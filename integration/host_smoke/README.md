# Peanut-GB host smoke test

This is a toolchain-independent smoke check for the vendored emulator header. It does not emulate the X4 Pro HAL.

From the CrossInk repository root:

```bash
./integration/host_smoke/build_and_run.sh
```

The same command also tests Walnut-CGB frame callbacks, checks RGB565-to-monochrome conversion for black/white/primary colors/mid-gray, and verifies that the two core objects link together without duplicate symbols.

## Game Boy Color speedup checks

```bash
./integration/host_smoke/run_cgb_speed_tests.sh
```

Runs, under AddressSanitizer and UndefinedBehaviorSanitizer:

- `cgb_dither_test.cpp`: `src/activities/gameboy/CgbDither.h` produces exactly the framebuffer of the per-pixel
  Floyd-Steinberg it replaced (kept in the test, verbatim, as the reference), in both orientations and at every scale.
- `walnut_cgb_equiv_test.c`: the luminance tables equal the per-pixel conversion for all 65,536 colours; a run that
  skips composing most frames ends every frame with byte-identical emulator state to a run that composes them all
  (and the frames it does compose match pixel for pixel); the internal-RAM/PSRAM allocation rules hold and nothing leaks.
  It runs `cgb_test_rom.h`, a synthetic CGB ROM generated by `gen_cgb_test_rom.py` that moves scroll, window, sprites and
  palettes every frame and uses both VRAM banks, HDMA and double speed.
- `walnut_cgb_smoke.c`: the bridge still runs a ROM end to end.

These prove the changes do not alter what the emulator computes or draws. They say nothing about how fast it runs on the
ESP32; for that, compare `/.crosspoint/gameboy-perf.txt` before and after on the device.
